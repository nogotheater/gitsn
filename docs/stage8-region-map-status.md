## 고객사(Customer)가 만들어지거나 바뀌는 경로 (2단계 조사)
| 경로 | 위치 | 소재지·기관 유형 처리 |
|---|---|---|
| 기획팀 고객사 등록·수정 | `delivery/services/planning.py` `save_presentation` | 4단계에서 자동 채움·수정 칸 추가 예정. 그 전까지 새 고객사는 비어 있고 지도에 "지도에 올리지 못한 기관"으로 안내된다 |
| 고객사 생성 함수 | `delivery/services/presentations.py` `new_customer` | 위 경로와 검증 스크립트가 쓴다. 지도용 칸은 기본값(빈 값) |
| 중복 통합 | `delivery/services/duplicates.py` | 유지 고객사의 값이 남는다. 통합된 고객사는 집계·목록에서 빠지므로 지도에도 나오지 않는다. 4단계에서 "유지 고객사 소재지가 비면 통합 대상 값으로 채움"을 검토 |
| 일회성 자료 입력 | 7단계 `import_to_db.py`(프로젝트에 없음) | 다시 쓰면 3단계 `fill_locations`를 이어서 돌린다 |
| Django admin | 설치돼 있으나 URL에 연결되지 않음 | 해당 없음 |

## 개발용 실행 설정
- `compose.map-dev.yaml`은 지도 작업 중에만 쓴 개발 전용 설정이다(코드 폴더 연결, 자동 재시작, 브라우저 검사 켬). 자동으로 적용되지 않으며 운영에는 쓰지 않는다.
- 원래 방식: `docker compose up -d --build --wait`

## 범위 밖으로 남은 것
- 4단계: 기획팀 고객사 화면의 소재지·기관 유형 입력 칸(저장 시 자동 채움, 이름 변경 경고, 중복 통합 시 소재지 규칙). 그 전까지 새 지자체·의회 고객사는 "지도에 올리지 못한 기관"으로 안내되고, `fill_locations`로 채운다.
- 점검 때 다시 볼 것: 자유 확대(휠·두 손가락), 전환 버튼 디자인.
- 도청 보안 계약의 계약일이 대부분 비어 있어 도입 연도가 "—"로 보인다. 계약일을 입력하면 자동 반영된다. (후속: 다른 부서에 자료를 요청해 입력 — 형우 2026-10-21)
- 4단계는 이번 범위에서 빼고 후속 작업으로 둔다(형우 2026-10-21).
- 인천 중구 → 영종구: 형우가 고객사 이름을 "인천광역시 영종구"로 바꿈(2026-10-21). 동구 → 제물포구는 해당 고객사가 없음.
- 미룬 리뷰 항목: 19(지도 전체 키보드 조작), 31, 35, 36.

- 시스템의 지자체·의회 고객사는 177곳이다. 지도는 175곳을 쓴다.
- 차이 2곳은 고객사 목록에서 숨긴 곳(show_in_list=False)이다: 대전광역시사회서비스원, 상주은모래비치. 목록에서 숨긴 고객사는 지도에서도 뺀다(리뷰 14 결정).
