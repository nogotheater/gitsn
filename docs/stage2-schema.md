# 2단계 기본 모델과 검증 범위
상태: 모델·초기 마이그레이션 파일 작성, 실제 PostgreSQL 적용 미완료.

| 모델 | 역할 | 현재 구현 |
|---|---|---|
| Organization | 기관·계약 당사자 원본 | 안정 식별값·공식 명칭. 명칭 자동 중복 통합 없음 |
| Customer | 실제 도입 고객사와 실적 설정 | 기관 원본 재사용, 단일 분류·지역·집계·개별 공개·로고·메모 |
| Contract | 계약 원본 | 계약 당사자 1곳, 도입 고객사 1곳, 계약일 선택, 유효 여부, 선택 메일 제목·수신일·발신자 |
| Product | 제품 종류 | 코드·제품명·마킹·색상. 실제 제품 목록·색상 초기 자료 미입력 |
| ContractProduct | 계약별 제품 수량 원본 | 계약/제품 조합 중복 금지, 수량 1 이상 정수 |
| InstallationSite | 물리적 설치 장소 | 안정 식별값·명칭. 장소 소유 기관의 자동 변경 규칙 미구현 |
| ContractSite | 계약과 설치 장소 연결 | 같은 계약/장소 중복 연결 금지 |
| SiteProductSelection | 장소별 실제 제품 선택 | 해당 계약 제품만 연결. 장소별 수량 없음 |
| SitePresentation | 장소의 별도 실적 표시 설정 | 선택적으로 생성. 기본 집계 제외. 분류·공개값은 별도 설정 |
| UserAccessProfile | 직원·파트너사 열람 구분 | 기획팀은 별도 Django 관리 권한 사용. 실제 계정 미생성 |

## 수량 규칙 — 사용자 확정
- 1 이상 정수만 허용. 0·음수·소수·미입력은 거부한다.
- 문자열 숫자는 정수로 파싱하지만 소수·지수 표기는 허용하지 않는다.
- 실수형·불리언을 정수로 잘라 저장하지 않는다.
- 최대 저장 범위는 PostgreSQL bigint의 기술 한계다. 별도 임의 업무 상한을 만들지 않았다.
- Python 파싱, Django 폼/필드, DB 양수 제약을 작성했다.
- DB 제약의 실제 실행 결과는 PostgreSQL 연결 후 검증해야 한다.

## 아직 구현하지 않은 정책
- 목록 표시와 집계는 독립으로 확정. 신규 표시 화면의 세부 동작은 후속 단계.
- 같은 장소의 여러 기관 공유·소속 변경 처리.
- 분류 전체 비공개와 개별 공개값의 우선순위.
- 종료 계약 기록 보존·현재 실적 제외는 확정. 실제 DB 조회·보관 검증은 남아 있음.
- 계정 발급·재설정 주기.
- 지역 상세 대응표와 예외 장소 분류.
- 실제 DB 조회·권한별 응답 서비스와 화면.

## 기술적 보존 원칙
- 참조 중인 기록은 PROTECT 연결로 실수 삭제를 방지한다. 업무상 영구 보존 정책을 확정했다는 뜻은 아니다.
- 장소에 고정 소유 고객사를 강제하는 필드를 만들지 않고 계약 연결에 실제 도입 고객사를 보존했다.
- 표출 종류는 고객사/장소 표시 설정 기록을 구분해 표현한다. 미정인 동시 표출 정책은 자동 적용하지 않는다.
- 장소별 제품의 계약 일치는 모델 clean/save에서 확인한다. DB를 직접 수정하거나 검증을 우회하는 bulk 연산은 사용하지 않는다.
- 실제 PostgreSQL 통합 검증에서 교차 연결 거부와 중복·양수 제약을 다시 확인해야 한다.

## 실제 확인 결과
- manage.py check 통과.
- manage.py test: DB를 사용하지 않는 21개 테스트 통과.
- makemigrations delivery로 0001_initial.py 생성.
- makemigrations delivery --check --dry-run: 모델과 변경 파일 간 차이 없음.
- DB 연결이 없어서 마이그레이션 이력 검사 경고 발생. 이를 성공한 DB 검증으로 처리하지 않음.
- migrate, SQL 제약 실행, 재적용, 저장 후 재조회는 수행하지 못함.

## 종료 계약 정책 — 사용자 확정
현재 제품 마킹·수량 합계는 유효 계약만 기준으로 계산한다. 종료 계약 원본·제품·수량은 과거 기록으로 유지한다. 같은 제품의 다른 유효 계약이 남으면 마킹을 유지하고 유효 수량만 합산한다. 모든 계약 종료 시 현재 목록·집계에서 빠지지만 기록은 삭제하지 않는다.
내부 ORM 조회 파일은 작성했으며 실제 DB 실행은 미검증이다. 현재 자료와 과거 기록을 섞어 합산하지 않는다.

## 계약 메일 정보 — 사용자 확정
메일 제목·수신일・발신자는 모두 선택 입력이며 전부 비어 있어도 된다. 수신일은 날짜만 기록하고 발신자는 이름 또는 이메일을 허용한다. 원본 메일·첨부파일은 저장하지 않는다. 제목 512자·발신자 255자는 기술상 입력 길이로, 향후 폼에서 안내한다. 출처 열람은 기획팀만 허용한다.

## 제품 복수 선택 — 사용자 확정
제품은 복수 선택하며 선택한 제품을 모두 가진 동일 고객사만 조회·집계한다. C와 I를 고르면 한 제품만 도입한 고객사는 제외한다. 같은 고객사의 서로 다른 유효 계약 제품도 합쳐 판단한다. 종료 계약 제품은 제외하며 제품 미선택 시 제한하지 않는다. 장소 별도 실적에는 해당 장소의 실제 제품만 적용한다. 목록·총수·분류별 수·비공개 수·출력에 같은 조건을 적용한다. 현재 코드는 내부 조회만 작성했으며 권한별 응답·화면·출력 연결과 실제 DB 실행은 미검증이다.

## 목록 표시와 집계 — 사용자 확정
목록 표시(show_in_list)와 고객사 수 포함(include_in_total)은 각각 저장한다. 집계 제외 장소도 표시 가능하고 목록에서 숨겨도 집계 설정을 덮어쓰지 않는다. 시청과 해수욕장 모두 표시·시청만 집계 시 목록 2개/총 1곳, 장소 포함 시 목록 수 그대로/총 2곳이다. 공개 설정은 별도이며 비공개 개별 정보의 파트너사 제공은 금지한다. 물리적 설치 장소만 등록하면 목록 항목이 생기지 않는다. 기존 표시용 기록의 노출을 유지하도록 show_in_list를 True로 초기화하며 기획팀이 별도 변경할 수 있다. 현재 계약·제품 조건은 목록 후보와 집계 후보에 공통 적용하고 목록 표시 필터를 집계에 사용하지 않는다. 분류 조건 및 권한별 응답·화면 연결은 별도 검증이 필요하다.
