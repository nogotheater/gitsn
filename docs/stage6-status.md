# 6단계 — 수동 중복 통합 (2026-10-19)

## 이번 구현

| 항목 | 구현 내용 |
|---|---|
| 중복 선택 | 고객사 상세의 "중복 통합" 버튼에서 유지할 고객사를 기준으로, 통합될 중복 고객사 한 곳 이상을 검색·체크로 선택. 자동 중복 판별은 하지 않으며 기획팀이 직접 확인하고 선택 |
| 상충값 선택 | 통합 검토 화면에서 기존 고객사 수정과 같은 입력(명칭·분류·지역·집계·목록 표시·표시 구분·파트너 공개·심볼·메모)으로 유지할 고객사의 최종값을 선택·수정. 중복 고객사의 현재값은 참고로 표시 |
| 계약 처리 | 중복 고객사의 유효 계약마다 "새 계약으로 포함" 또는 "기존 계약과 동일(중복, 제외)" 중 선택. 제외를 고르면 유지할 고객사의 어느 기존 계약과 같은지 직접 지정 |
| 중복 계약 제외 | 제외로 표시한 계약은 종료 상태(is_active=False)로 바뀌고 지정한 계약을 가리키는 superseded_by가 저장됨. 과거 기록은 유지되며 현재 수량 합계·제품 마킹에는 반영되지 않음 |
| 이중 합산 방지 | 같은 실적을 중복 입력한 계약을 "제외"로 처리하면 합산에서 빠진다. 서로 다른 실제 계약은 "포함"으로 각각 더해진다 |
| 종료 계약 자동 이전 | 중복 고객사의 이미 종료된 계약은 선택 없이 과거 기록으로 유지할 고객사에 자동으로 옮겨진다. 다시 활성화되지 않는다 |
| 계약 당사자 보존 | 계약을 옮길 때 customer(실제 도입 고객사)만 유지할 고객사로 바뀐다. contracting_party(실제 계약 당사자 기관)는 바꾸지 않아 원래 계약 체결 주체 기록이 유지된다 |
| 통합 결과 | 중복 고객사는 삭제하지 않고 merged_into/merged_at만 기록하고 집계·목록에서 제외(include_in_total=False, show_in_list=False)한다. 고객사 상세에 통합 안내와 유지 고객사 링크가 표시되며 정보 수정·계약 등록은 막힌다 |
| 트랜잭션 | 상충값 저장부터 계약 이전, 중복 고객사 표시까지 하나의 DB 트랜잭션으로 처리한다. 검증 실패나 도중 오류가 나면 전부 취소되고 이름 변경을 포함해 아무것도 바뀌지 않는다 |
| 권한 | 기존 기획팀 전용 경로와 동일하게 manage_delivery 권한이 없으면 모든 중복 통합 경로를 거부한다 |

## 완료 기준 확인

- 같은 계약을 중복 연결한 사례(10대 + 10대)를 "제외"로 처리하면 20대로 합산되지 않고 10대로 유지됨을 자동 검사와 실제 브라우저 양쪽에서 확인했다.
- 서로 다른 실제 계약(10대 + 5대)을 "포함"으로 두면 15대로 합산됨을 확인했다.
- 통합 후 중복 고객사의 명칭·ID 표시가 목록·검색에서 사라지고, 계약·설치 장소 연결은 유지됨을 확인했다.
- 계약 처리 방법을 비워 두거나 의도적으로 한 계약의 결정을 누락시킨 사례에서, 이미 적용된 명칭 변경을 포함해 아무 것도 저장되지 않음을 확인했다(트랜잭션 롤백).
- 기획팀 권한이 없는 직원·파트너사·비로그인 요청은 중복 통합 화면·제출 모두 403/로그인 이동으로 거부됨을 확인했다.

## 실제 적용·확인

로컬 Docker(Python 3.12.14 · Django 5.2.18 · PostgreSQL 17.11, 고정 스택 변경 없음)에서 마이그레이션 0005를 실제로 적용하고, 전체 116개(기존 101개 + 이번 15개) 자동 검사를 통과했다. 이후 실제 웹 화면에서 기획팀 계정으로 로그인해 중복 고객사 2곳을 만들고, 검색 → 선택 → 검토(상충값·계약 처리) → 제출까지 실제로 실행해 10대+5대가 15대로 합산되는 것과 중복 고객사 상세의 통합 안내 배너를 직접 확인했다. 확인에 사용한 계정·고객사·계약은 확인 후 모두 정리했다.

## 남은 사항과 범위

- 중복 통합은 고객사(실제 도입 고객사) 단위만 다룬다. 설치 장소(SitePresentation) 중복 통합은 이번 범위가 아니며, 6단계 지시문도 고객사만 명시한다.
- 통합 취소(undo)는 만들지 않았다. 잘못 통합한 경우 현재는 되돌리는 화면이 없다. 필요하면 별도로 논의한다.
- 한 번에 여러 중복 고객사를 같은 유지 고객사로 통합할 수 있으나, 각 중복 고객사의 활성 계약마다 개별 결정이 필요하다. 계약 수가 많은 사례의 화면 구성(목록이 긴 경우의 스크롤·레이아웃)은 실사용 자료로 추가 확인이 필요하다.
- 7단계 엑셀 대조·전체 완료 확인과 운영 배포는 이번 범위가 아니다.
