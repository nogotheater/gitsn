## 구현한 범위
- 공통 로그인: 직원·파트너사·기획팀의 활성 계정과 설정된 열람 범위를 검사한다. 관리자 로그인 기본 이동은 기존 기획팀 화면, 직원/파트너사는 실적 현황이다. 주소를 직접 열어도 서버에서 권한을 다시 검사한다. 로그아웃은 POST만 허용한다.
- /performance/: 기존 공통 집계·공개 범위 서비스를 재사용한다. 제품은 복수 선택 AND이며 같은 고객사의 서로 다른 유효 계약 제품도 합쳐 판단한다. 장소는 그 장소에 실제로 지정된 제품만 기준이다. 제품 미선택은 전체다. 분류·지역 조건은 제품 조건과 함께 적용한다.
- 총고객사 수와 분류별 수는 페이지의 행 수와 별개다. 파트너사는 공개 항목만 목록으로, 비공개 고객사는 숫자로 본다. 같은 조건의 총수는 직원과 같다. 집계 제외 장소는 목록에 있어도 총수를 늘리지 않는다. 모든 유효 계약이 끝난 대상은 현재 집계에서 제외된다.
- 목록에는 수량·계약·참고 메모·메일 출처를 넣지 않는다. 파트너사 HTML에 비공개 명칭·식별값·로고 주소·개별 제품·계약을 넣지 않으며 직원용 상세 링크도 제공하지 않는다.
- 직원용 고객사 상세: 제품별 유효 수량 합계와 종료 계약을 포함한 내역. 직원용 계약 상세: 계약 당사자·실제 고객사·제품/전체 수량·설치 장소/실제 제품·유효 여부. 직원용 장소 상세는 연결 계약을 보여주며 장소별 수량을 만들지 않는다. 메일 출처와 메모는 직원용 상세에 제공하지 않고 기존 기획팀 화면을 사용한다.
- 로고는 /performance/logos/에서 로그인·권한·현재 공개 설정을 검사한다. 파트너사는 공개·목록 표시·유효 계약이 있는 대상의 로고만 조회할 수 있다. 원래 저장 경로/파일명을 응답에 넣지 않고 no-store로 제공한다. 직접 /media/ 공개 제공은 추가하지 않았다.
- 기획팀 계정 관리: 계정 검색/생성, 표시 이름/직원·파트너사·기획팀 권한/접속 허용 수정, 수동 비밀번호 재설정. 기존 비밀번호·해시는 화면에 제공하지 않는다. 비밀번호 검증과 해시를 재사용하며 실패 입력에서 비밀번호를 다시 표시하지 않는다.
- 계정 변경은 트랜잭션과 계정 잠금으로 직렬화하며 잠금 후 작업자의 현재 권한을 다시 확인한다. 오래된 설정 화면의 덮어쓰기를 거부한다. 본인의 기획팀 권한·접속 허용 해제를 막아 관리자 부재를 방지한다. 별도 staff/superuser/그룹 권한 계정은 이 간단 관리 화면에서 변경하지 않는다.
- 권한·접속 허용 변경은 다음 요청부터 반영된다. 비밀번호 재설정 후 기존 세션은 다음 요청에서 거부된다. 본인 비밀번호를 바꾸면 즉시 로그아웃하여 새 비밀번호로 다시 로그인한다. 계정 안내 메시지·이메일은 자동 발송하지 않는다.
