## 기존 윈도우 프로젝트 적용

GITSN_ui_update_fix_v3.py를 manage.py·compose.yaml이 있는 기존 gitsn-delivery 폴더에 넣는다. Docker Desktop과DB가 실행 중인 상태에서 해당 폴더PowerShell에서 실행한다.

```powershell
docker compose run --rm --no-deps -T --user 0 --volume "$($PWD.Path):/app" web python GITSN_ui_update_fix_v3.py 2>&1 | Tee-Object -FilePath ui-update-fix-v3-result.txt
```

시작 GITSN_UI_UPDATE_REVISION_FIX3, 전체101개 OK, STAGE5_PRINT_CHECKS_OK, GITSN_UI_UPDATE_AND_CHECKS_OK를 확인한 뒤 새 웹을 반영한다.

```powershell
docker compose up -d --build --wait --wait-timeout 180
```

그 후 http://localhost:8000/performance/ 에서 Ctrl+F5로 새로고침한다. 검사가 실패하면 재구성하지 말고 ui-update-fix-v3-result.txt를 확인한다. 로그가 끝날 때까지 기존PowerShell을 닫지 않는다.

확인된 이전/현재 파일 해시만 허용하고 임의 편집은 쓰기 전에 중단한다. --check는 사전검사만, --apply-only는 검증 없이 파일만 적용하는 유지보수용이다. 정상 사용은 위 기본 명령을 사용한다. 이전 단계 파일 이름이 비슷하므로 이번에는 GITSN_ui_update_fix_v3.py를 사용한다.
.env·암호·기존 고객사/계약/계정·DB볼륨·원본 로고를 덮어쓰지 않는다. 검사용 자료는 임의 이름의 분리된 테스트DB에서만 만들고 정리한다. 6단계 중복 통합/7단계 엑셀 이전/운영 배포는 이번 범위가 아니다.

## 납품현황 조회 UI 수정 — 2026-10-19
사용자가 도입 제품·고객 분류 조회 UI를 직접 검토해 달라고 요청했다. 검토 결과 "도입 제품"·"고객 분류" 버튼 2개가 실제로는 같은 통합 패널을 여는 점, 적용 조건이 버튼 2곳과 하단 문구 3곳에 중복 표시되는 점, 툴바와 패널 내부에 "초기화"가 두 번 있는 점, 고객 분류가 드롭다운 안에 있어 자주 쓰는 단일 분류 조회도 여러 클릭이 필요한 점을 문제로 확인했다. 사용자는 이 중 고객 분류의 칩/탭 전환과 중복 제거를 우선 적용해 달라고 결정했다.

적용한 변경:
- 고객 분류를 패널 밖 칩(버튼형 링크) 목록으로 꺼내 1클릭으로 전환하게 했다. 칩은 현재 선택된 제품 조건은 유지하고, 지방자치단체·의회 사이에서만 지역을 유지하며 다른 분류로 가면 지역을 지운다. 기존 폼의 분류·지역 유효성 규칙(services/forms)은 바꾸지 않았다.
- "도입 제품"·"고객 분류" 버튼을 "제품·지역 필터" 버튼 하나로 합쳤다. 패널에서 고객 분류 입력은 제거하고 현재 분류를 숨은 필드로만 전달한다.
- 패널 내부의 "초기화" 버튼을 없애고 툴바의 "초기화" 하나만 남겼다. 데스크탑에만 있던 초기화 링크를 모바일 툴바에도 추가해 기능 손실 없이 중복만 줄였다.
- 적용 조건 문구(`적용 조건 · ...`)는 인쇄 폴백·접근성 텍스트 역할이 있어 유지했다. 분류 카운트가 상단 요약과 분류별 섹션 제목에 두 번 나오는 부분은 이번 범위로 보지 않고 그대로 두었다(기존 검토에서도 낮은 우선순위로 분류함).
- 수정 중 `has_filters` 계산이 실제 조건과 무관하게 항상 참이 되는 기존 결함을 발견해 함께 고쳤다(제품 목록이 비어 있어도 QueryDict에 키가 남아 `bool(query)`가 항상 참이 되던 문제). 조건이 전혀 없을 때는 초기화 링크가 더 이상 표시되지 않는다.

검증: 전체 자동 검사 116개(Chromium 포함)를 실사용자 PC와 동일한 조건(docker compose, 실제 PostgreSQL, 실제 Chromium)에서 통과했다. 분류 전환·지역 유지/초기화·패널 취소 시 선택 초기화 시나리오를 Playwright로 다시 작성해 통과시켰다(`delivery/tests/test_portal_browser.py`). 실제 웹 화면에서 로그인해 분류 칩 클릭 1회로 전체 화면이 즉시 바뀌는 것과, 조건이 없을 때 초기화 링크가 보이지 않는 것을 직접 확인했다.

변경 파일: `delivery/portal_views.py`(칩 데이터 생성, has_filters 수정), `templates/portal/performance.html`, `static/delivery/performance.js`, `static/delivery/portal.css`, `delivery/tests/test_portal_browser.py`. 업무 규칙·모델·마이그레이션 변경은 없다.

사용자가 제공한 "지슨 주요고객사 시안.html"을 기준으로 필터·분류 UI를 다시 구성했다. 결정은 항목별로 사용자에게 하나씩 확인해 확정했다.

확정 사항:
- 제품 복수 선택은 "하나 이상 도입"(OR)이 맞다. 지시문 63행과 stage2-data-design의 "모두 도입" 문구를 이에 맞게 갱신했다.
- 고객 분류는 상단 고정(sticky) **탭**으로 전환하고 **여러 분류를 동시에 선택**할 수 있다(탭을 누를 때마다 켜고 끔, "전체"는 모두 해제). 탭에는 수량을 표시하지 않는다. 상단 분류별 집계 스트립은 분류를 하나도 고르지 않았을 때만 표시한다.
- 탭 라벨은 시안과 같은 짧은 표시명(전체·중앙정부·공공·지자체·지자체 의회·금융·교육·해외·민간)을 쓴다. DB 분류명·카드·상세·인쇄 문구는 원래 명칭 그대로다.
- 모바일 탭은 가로 스크롤 + 양끝 페이드 + 좌우 이동 버튼이다. 선택된 탭은 로드 시 가운데로 맞춘다.
- **지역 조회 조건은 제거**했다(폼·링크·인쇄 조건 모두). 고객사 카드·상세에 표시되는 지역 표기는 유지한다.
- 제품은 "제품 필터" 버튼 → 색상 마크가 붙은 칩. 데스크톱은 칩을 누르면 바로 적용(GET 이동)되고 패널은 열림 상태를 기억해 연속 선택이 가능하다. 모바일은 바텀시트에서 고른 뒤 "적용" 버튼으로 반영하고, 닫으면 선택을 되돌린다. 버튼에는 선택 개수 배지를 표시한다.
- **기관명 검색**을 추가했다. 검색은 화면 목록만 좁히며 총고객사 수·분류별 수·인쇄/PDF에는 영향을 주지 않는다(파트너사가 비공개 고객사명을 수량 변화로 추정하지 못하게 하기 위함). 검색어는 페이지 이동 링크에는 유지되고 인쇄 링크에는 포함되지 않는다.
- **카드/리스트 보기 토글**을 추가했다. 브라우저에 기억되며 기본값은 데스크톱 카드·모바일 리스트다. 서버 상태와 무관하다.
- 적용 중인 조건은 결과 줄에 제품 칩(×로 개별 해제)·분류 문구·검색어 칩으로 표시하고 "모두 해제" 하나로 전부 지운다. 기존 "적용 조건 · …" 문구와 툴바 초기화 링크는 이것으로 대체했다. 제품 마크 범례를 결과 줄에 상시 표시한다.
- 빈 결과와 잘못된 조건(400) 화면에 조건 칩과 "필터 모두 해제"/"조건 모두 해제" 링크를 두었다. 모바일 하단 바는 "제품 필터"·"인쇄·PDF" 두 개다.
- 시안의 보안 분야 필터·기간/이달 신규·정렬 토글·민간 비밀번호 잠금은 적용하지 않았다(PRD 범위 밖 또는 기존 공개 규칙과 충돌).
- 남은 문구 통일: 403·출력 오류·고객사/장소 상세의 "실적 현황"을 "납품현황"으로 바꿨다.

구현: `category`는 복수 값(`?category=a&category=b`)이며 폼에서 확정 순서로 정렬한다. `current_performance_payload`는 `categories=()`를 받고 `category__in`으로 조회한다. 인쇄 경로(`print_views`, `services/printing`, `print_document.html`)도 복수 분류를 그대로 쓴다. 탭·칩 링크는 서버에서 만든다(`filter_query`/`filter_url`).

검증: 전체 117개(Chromium 브라우저 검사 포함)를 docker compose·실제 PostgreSQL·실제 Chromium에서 통과했다. 브라우저 시나리오는 탭 복수 선택/해제, 데스크톱 칩 즉시 적용과 패널 유지, 활성 칩 해제, 검색이 수량을 바꾸지 않음, 보기 토글 기억, 모바일 탭 이동 버튼, 바텀시트 적용/취소, 모두 해제를 다시 작성했다.

변경 파일: `delivery/portal_forms.py`, `delivery/portal_views.py`, `delivery/print_views.py`, `delivery/services/audience_performance.py`, `delivery/services/printing.py`, `templates/portal/performance.html`, `templates/portal/print_document.html`, `templates/portal/print_error.html`, `templates/portal/customer_detail.html`, `templates/portal/site_detail.html`, `templates/403.html`, `static/delivery/performance.js`, `static/delivery/portal.css`, 검사 5개 파일, 문서 2개. 모델·마이그레이션 변경은 없다.
