## 실행 전 규칙
너는 이 문서에 따라 웹페이지를 구현하는 코딩 에이전트다.
지금은 구현을 시작하지 말고 마지막에 사용자에게 “몇 단계부터 시작할까요?”라고 질문하라.
사용자가 시작 단계를 지정한 뒤 그 단계만 수행하고, 완료 결과와 다음 단계를 보고하라. 이후 단계까지 자동으로 진행하지 마라.
중간 단계부터 시작하면 선행 단계의 산출물을 읽고 완료 기준 충족 여부를 확인하라. 선행 자료가 없으면 필요한 항목만 확인하고, 이미 확정된 질문을 반복하지 마라.
[확인 필요] 항목은 미정 사항이다. 임의로 기본값을 확정하거나 완료로 처리하지 마라. 해당 항목에 의존하지 않는 작업은 진행할 수 있다.
[기술 선택]은 원본 PRD에 없던 사항을 이번 지시문에서 정한 구현 방식이다. 업무 규칙과 혼동하지 마라.
기존 저장소가 있으면 먼저 읽고 충돌을 보고하라. 고정 스택으로 전환하기 위해 기존 코드를 임의로 삭제하지 마라.
실제 고객사·계약을 추측해 만들지 말고, 초기 구현과 검증은 가상 자료로 진행하라.

## 목적과 핵심 기능
목적: 기획팀이 계약 기준 실적을 한 번 입력하고, 영업 담당자가 PPT 재작성 없이 조회·출력·PDF 저장한다. 납품 완료 추적 도구가 아니다.

1. 고객사·계약 관리: 등록·수정, 제품·수량, 장소별 제품, 유효 여부, 집계·표시·공개 설정, 수동 중복 통합.
2. 실적 조회·집계: 제품·고객 분류별 조회, 카드/리스트, 제품 마킹, 직원용 합계, 파트너사용 비공개 수.
3. 고객사 리스트 출력·PDF: 로고·고객사명·제품·전체 및 분류별 고객사 수. 계약 상세·수량은 제외.

로그인과 계정 관리는 세 기능의 공통 조건이다.

## 변경하면 안 되는 업무 규칙

### 사용자와 권한
- 영업 담당자·대표는 직원 열람 범위다. 기획팀은 직원 중 정보·계정 관리 권한을 가진다.
- 파트너사는 모두 같은 공개 범위를 사용한다.
- 비로그인 이용자는 고객 정보를 볼 수 없다.
- 일반 직원·파트너사는 정보와 계정을 수정할 수 없다.
- 출처 정보는 기획팀만 열람한다.
- 기획팀이 아이디·비밀번호를 관리하고 수동 재설정한다. 발급 단위·재설정 주기는 [확인 필요].
- 비밀번호를 평문으로 저장하거나 조회 화면에 노출하지 마라. 재설정으로 관리하라.

### 관계·집계·제품
- 계약 당사자, 실제 도입 고객사, 설치 장소를 구분하고 관계를 보존한다.
- 기본 중복 판단은 계약 당사자 기준이지만, 기획팀이 설치 장소를 별도 실적 대상으로 추가할 수 있다.
- 고객사 수에 포함할지, 고객사/설치 장소로 표시할지, 파트너사에 공개할지는 독립된 설정이다.
- 집계 대상으로 선택한 동일 고객사는 계약·제품·구매 수량과 관계없이 한 곳으로 센다.
- 신규 고객사는 기본 집계 포함, 설치 장소는 기본 제외다. 기획팀이 예외 장소를 포함으로 변경하면 독립 집계한다. 초기값을 기존 저장값에 재적용하지 않고 공개 여부와 별도로 관리한다.
- 같은 장소의 추가 계약은 기록하되 새 목록 항목을 만들지 않는다. 다른 제품이 추가되면 기존 항목의 제품 마킹을 추가한다.
- 제품 검색은 복수 선택을 허용하며 선택한 제품 중 하나 이상을 도입한 고객사를 조회한다. C와 I 선택 시 C만 도입한 고객사도 포함한다. (2026-10-19 사용자 확정: 5단계에서 '모두 도입'에서 '하나 이상 도입'으로 변경한 것을 원본 규칙에 반영.) 고객 분류도 복수 선택할 수 있으며 선택한 분류 중 하나에 속하면 포함한다. 같은 고객사의 서로 다른 유효 계약에 C와 I가 있어도 포함하며 종료 계약 제품은 조건 충족에 사용하지 않는다. 제품을 선택하지 않으면 제품으로 제한하지 않는다. 설치 장소를 별도 표시할 때에는 해당 장소에 선택된 실제 제품으로 같은 조건을 판단한다. 목록·조건별 총수·분류별 수·파트너사 비공개 수·출력 대상에 동일한 조건을 사용한다.
- Alpha-C는 C, Alpha-I는 I로 색상과 알파벳을 함께 표시한다. 나머지 제품 목록·기호·색상은 [확인 필요].
- 제품·수량은 계약에 한 번만 입력한다. 고객사 상세는 계약 자료를 합산해 보여준다.
- 제품 수량은 1 이상의 정수만 허용하며 0·음수·소수·미입력은 거부한다. 소수를 정수로 잘라 저장하지 마라. 별도 업무 상한은 추가하지 않되 저장 자료형의 기술적 한계는 검증한다.
- 계약별 C 10대와 C 5대는 기록을 보존하고 직원용 고객사 상세에 합계 15대를 표시한다.
- 주요 목록·출력·PDF에는 수량을 표시하지 않는다.
- 계약 한 건에는 실제 도입 고객사 한 곳만 연결한다(A 방식). 고객사 한 곳에 여러 계약을 연결할 수 있다.
- 한 계약은 여러 제품과 여러 설치 장소를 연결할 수 있다. 장소별 수량은 관리하지 않는다.
- 장소별 실제 설치 제품은 기획팀이 해당 계약의 제품 중 선택한다(B 방식).
- 장소 A에 C만 선택했다면 그 장소의 표시·제품별 조회도 C만 기준으로 한다. 계약 전체 제품을 모든 장소에 자동 복제하지 않는다.
- 한 계약이 여러 표시 대상과 연결되어도 같은 계약의 수량을 고객사 합계에서 이중으로 더하지 않는다.
- 초기 집계값은 위 확정 기준을 적용한다. 목록 표시 여부와 고객사 수 포함 여부는 각각 저장·변경한다. 집계에서 제외한 장소도 목록에 표시할 수 있으며 목록에서 숨겨도 집계 설정을 자동 변경하지 않는다. 설치 장소만 등록하면 목록 항목을 자동 생성하지 않는다. 표시용 기록을 만드는 경우 목록 표시로 초기화하고 기획팀이 끌 수 있게 한다. 장소의 여러 기관 공유 등 실제 연결 예외는 [확인 필요].

### 분류·공개
- 고객 분류는 단일 선택: 중앙정부, 공공기관, 지방자치단체, 지방자치단체 의회, 금융, 교육, 해외, 민간.
- 해외 금융기관은 금융보다 해외를 우선한다.
- 서울시청과 서울시의회는 별도 고객사다.
- 지방자치단체·의회는 수도권·충청권·호남권·영남권·강원권으로 세분한다. 제주 등 상세 지역 대응표와 예외 장소 분류는 [확인 필요].
- 신규 민간 고객사는 기본 비공개, 나머지 분류는 기본 공개다. 기획팀이 개별 변경할 수 있다.
- 고객 분류를 변경하면 공개 여부도 새 분류의 기본값으로 바꾼다.
- 분류 단위 대외비 지정과 개별 공개 설정이 충돌할 때 우선순위는 [확인 필요].
- 파트너사에는 공개 고객사만 개별 표시하고 비공개 고객사는 숫자로만 표시한다.
- 전체 100곳 중 공개 70곳·비공개 30곳이면 파트너사는 공개 목록 70곳, 비공개 수 30곳, 총 100곳을 본다.
- 제품·분류 조건을 바꾸면 공개·비공개 모두 해당 조건에 맞게 집계한다. 같은 조건의 직원·파트너사 총수는 같다.
- 파트너사 응답의 HTML·데이터·PDF에 비공개 명칭·로고·개별 제품·계약 상세·출처를 넣지 마라. CSS로만 숨기는 방식은 금지한다.
- 목록 행 수를 고객사 수로 사용하지 마라. 시청은 집계 포함·장소는 집계 제외 상태에서 둘 다 표시하면 목록 2개·총 고객사 수 1곳이다. 장소를 집계에 포함하면 목록 추가 없이 총 2곳이다. 파트너사 공개 여부도 별도 적용하며 비공개 명칭은 목록에 제공하지 않는다.

### 계약 종료·중복 통합
- 렌탈 종료 등은 기획팀이 계약 유효 여부를 수정한다.
- 유효 계약이 하나라도 남으면 고객사 수를 유지한다. 15대 중 10대 계약이 종료되어 5대가 남아도 고객사 수는 유지된다.
- 유효 계약이 하나도 남지 않으면 목록·집계에서 제외한다.
- 현재 제품 마킹과 수량 합계는 유효한 계약만 기준으로 계산한다. 종료된 계약과 계약별 제품·수량은 과거 기록으로 보관한다. 같은 제품의 다른 유효 계약이 남으면 해당 마킹을 유지하고 그 유효 수량만 합산한다. 목록 제외를 영구 삭제로 해석하지 마라.
- 중복 고객사는 기획팀이 유지할 고객사를 선택해 계약을 모은다.
- 명칭·분류·공개 설정이 다르면 적용할 값을 먼저 선택한다.
- 통합 후 중복 표시 제거, 고객사 수·제품 마킹·수량 재계산, 계약·장소 관계 보존을 수행한다.
- 동일 계약을 두 번 합산하지 않는다. 통합은 DB 트랜잭션으로 처리하고 실패하면 전부 취소한다.

## 1단계 — 프로젝트 준비
작업:
- 기존 코드·실행 환경을 확인하고 프로젝트 구조와 고정 버전 목록을 작성한다.
- Django·PostgreSQL 개발 환경, 환경변수 예시, 로컬 실행 문서를 만든다.
- 환경변수에 비밀값을 두고 실제 비밀번호를 저장소에 넣지 않는다.
- 실제 고객 정보나 실제 운영 계정을 만들지 않는다.

완료 기준:
- 깨끗한 로컬 환경에서 문서대로 실행되고 DB 연결이 확인된다.
- Django 시스템 검사와 빈 프로젝트 테스트가 통과한다.
- 설치 버전·실행/중지 방법이 문서에 기록된다.
- 실제 배포·실제 자료 이전은 수행하지 않는다.

## 2단계 — 관계·업무 규칙 확정과 데이터 구조
작업:
- 확정된 계약당 고객사 1곳, 기본 집계값, 1 이상 정수 수량 규칙을 적용한다. 나머지 [확인 필요]인 장소의 여러 기관 공유 등 남은 미정 사항만 확인한다.
- 관계도와 항목표를 작성한 뒤 확정된 부분만 모델·마이그레이션으로 구현한다.
- 고객사, 계약 당사자, 설치 장소, 계약, 계약별 제품·수량, 장소별 제품 선택, 제품·분류·사용자 권한을 표현한다.
- 제품·수량을 고객사와 계약 양쪽에 중복 저장하지 않는다.
- 고객사 집계·조회 대상·직원/파트너사 투영을 공통 서비스로 분리해 이후 화면과 PDF가 재사용하게 한다.
- 단순히 조인한 행 수를 고객사 수로 세거나 장소 연결 개수만큼 수량을 곱하지 않는다.

완료 기준:
- 확정된 관계·기본값·허용 조합이 문서와 모델에 일치한다.
- 마이그레이션 적용·재적용 절차가 확인된다.
- 가상 자료에서 동일 고객사 추가 계약 시 1곳 유지, 계약별 10+5=15가 검증된다.
- 장소별 제품 선택과 예외 장소의 독립 집계가 확정 규칙대로 검증된다.
- C와 I 복수 선택 시 두 제품을 모두 가진 고객사만 조회·집계되며 서로 다른 유효 계약의 제품도 합쳐 판단한다. 종료 계약 제품이나 다른 장소의 제품으로 조건을 충족시키지 않는다.
- 목록 표시와 고객사 수 포함의 독립 변경이 검증된다. 시청·장소 모두 표시하되 장소 집계 제외 시 1곳, 장소 포함 시 2곳이다.
- 관계·집계에 영향을 주는 미정 사항은 통과로 표시하지 않는다.

## 3단계 — 기획팀 등록·수정·계약 종료
작업:
- 기존 고객사 검색 → 선택/신규 등록 → 계약·제품·수량 입력 → 장소 제품 선택 → 집계·표시·공개 설정 → 저장 흐름을 만든다.
- 기획팀 권한 검사를 등록·수정 서버 처리에 처음부터 적용한다. 4단계 전이라도 무권한 수정은 허용하지 않는다.
- 확정 입력 항목: 공식 명칭, 고객 분류, 제품·제품별 수량, 집계 포함 선택, 고객사/장소 표시 선택, 목록 표시 여부, 공개 여부.
- 지방자치단체·의회만 지역을 필수로 한다. 계약일·로고·참고 메모는 선택이다.
- 출처 정보는 계약별 메일 제목·수신일·발신자이며 모두 선택 입력이다. 수신일은 날짜만, 발신자는 이름 또는 이메일을 기록한다. 세 항목이 모두 비어 있어도 등록을 허용한다. 원본 파일 보관은 구현하지 않는다.
- 필수 누락·수량 오류를 항목별 안내하고 저장 실패 시 입력 내용을 유지한다.
- 종료 계약은 기록을 유지하되 현재 제품 마킹·수량·목록·집계에서 유효 계약 규칙을 적용한다.
- 마지막 수정일을 기록한다. 상세 변경 이력을 추가하지 않는다.

완료 기준:
- 계약일·로고·메모·메일 제목·수신일·발신자 없이 정상 저장되고 재접속 후 유지된다.
- 로고가 없으면 기본 표시가 나온다. 허용 파일 형식·용량은 확인 후 검증한다.
- 일반 직원·파트너사의 등록/수정 요청을 서버에서 거부한다.
- 전체 계약 종료 시 목록·집계 제외, 일부 유효 계약이 남으면 고객사 수 유지가 검증된다.
- 종료 계약 기록 보존, 유효 계약만의 제품 마킹·수량 합계, 같은 제품의 다른 유효 계약 유지가 검증된다.

## 4단계 — 로그인·계정 운영·조회 화면
작업:
- 로그인·로그아웃과 기획팀의 계정 관리·수동 비밀번호 재설정을 완성한다.
- 3단계의 관리 권한 검사를 모든 상세·조회·출력 진입점까지 확장한다.
- 실적 현황, 직원용 고객사 상세, 직원용 계약 상세를 구현한다.
- 현황: 로고·명칭·제품 마킹, 고객사 수·분류별 수, 조건 선택, 출력 진입.
- 고객사 상세: 제품별 합계·계약 목록. 계약 상세: 계약 당사자·제품별 수량·장소·유효 여부.
- 출처는 기획팀만 제공한다. 파트너사에 직원용 상세 링크·데이터를 제공하지 않는다.
- 데스크탑 카드형·모바일 리스트형으로 구성한다. 실제 색상·폰트·전환 폭·페이지 수·검색/정렬/조건 결합은 [확인 필요].
- 빈 결과는 결과 없음과 0곳을 표시한다.
- 필터를 URL 등 서버가 검증 가능한 상태로 유지해 출력 단계에서 재사용한다.

완료 기준:
- 공개 70·비공개 30의 자료에서 직원/파트너사 총수가 100으로 일치한다.
- 제품·분류 조건을 바꾸면 같은 조건의 총수와 비공개 수가 일치한다.
- 파트너사가 주소를 직접 입력해도 직원 상세·관리 기능에 접근하지 못한다.
- HTML·응답 데이터에 비공개 개별 정보와 계약·출처가 없다.
- 작은 모바일 화면과 데스크탑에서 주요 내용이 잘리지 않고 조작된다. 최종 검증 기기·브라우저는 [확인 필요].
- 공식 제품 마킹과 중복 없는 제품 표시가 확인된다.

## 5단계 — 고객사 리스트 출력·PDF
작업:
- 페이지 디자인을 먼저 검토받고 용지 방향·배치·페이지 나눔을 확인한다.
- 출력 대상이 현재 조건 전체인지 선택 고객사인지 [확인 필요]를 해결한다.
- 현재 이용자의 권한·조건으로 서버에서 출력 대상과 집계를 다시 계산한다.
- 같은 출력 템플릿으로 인쇄 미리보기와 PDF를 만든다.
- Playwright는 비공개 정보가 제거된 출력 데이터만 사용한다. 사용자가 준 임의 주소를 PDF 변환 대상으로 열지 않는다.
- PDF에 한글이 보이도록 글꼴을 포함하고 로고·텍스트 로딩 후 PDF를 생성한다.

완료 기준:
- 같은 조건의 화면·인쇄·PDF에서 대상과 고객사 수가 일치한다.
- 파트너사 PDF에 비공개 수와 동일한 총수가 나오고 비공개 개별 정보는 없다.
- 계약 상세·수량·출처가 인쇄·PDF에 없다.
- 한글·로고 누락, 고객사명 잘림, 부적절한 페이지 분할이 없다.
- 확인한 휴대폰·컴퓨터에서 PDF 다운로드가 동작한다.

## 6단계 — 수동 중복 통합
작업:
- 기획팀이 중복 대상과 유지할 고객사를 고르고 상충하는 명칭·분류·공개값을 선택하는 화면을 만든다.
- 통합 결과의 계약·장소 연결을 검증한 뒤 하나의 DB 트랜잭션으로 반영한다.
- 중복 계약은 한 번만 포함하고 고객사 수·제품 마킹·수량을 재계산한다.

완료 기준:
- 허용된 통합 사례에서 중복 표시가 제거되고 계약·장소 연결이 유지된다.
- 같은 계약 10대를 중복 연결한 경우 20대로 합산되지 않는다.
- 다른 계약 10대·5대는 15대로 합산된다.
- 중간 오류를 발생시켰을 때 통합 전 자료가 유지된다.
- 기획팀 외 이용자의 통합 요청을 거부한다.

## 7단계 — 실제 엑셀 대조·전체 완료 확인
작업:
- [확인 필요] 기존 엑셀 파일을 받아 열 구성·고객사 표기·제품·수량·누락·중복을 분석한다.
- 최초 이전 방식을 정하고 원본을 변경하지 않는 예비 변환 결과를 검토받는다.
- 반복 엑셀 업로드 기능을 별도 제품 기능으로 추가하지 않는다.
- 이전 전후 고객사 수·제품·수량과 예외 장소·공개 설정을 대조한다.
- 권한·집계·계약 종료·중복 통합·모바일·PDF의 전체 흐름을 검증한다.

완료 기준:
- 원본과 이전 결과의 차이가 설명되며 중복·누락이 처리된다.
- 모든 단계의 완료 기준과 확정된 예외 사례가 통과한다.
- 해결되지 않은 [확인 필요]를 완료로 숨기지 않고 목록으로 보고한다.
- 실행 문서·고정 버전·관리 방법·검증 결과가 준비된다.
- 배포와 실사용 전환은 별도 결정이다. 이 단계 완료만으로 자동 공개하지 않는다.

## Out of scope — 1차 버전에서 구현하지 말 것
- 보안 분야 입력·필터, 지도형 보기, 고객 제시용 별도 보기.
- 장소별 수량 관리, 납품 완료 추적, 메일 자동 입력.
- 원본 메일·계약서 파일 업로드·보관. 고객사 로고는 이 제외 대상이 아니다.
- PPT 자동 제작, 자유로운 PDF 편집기.
- 정식 수정 요청·승인 흐름, 상세 변경 이력, 사내 자료실 연결.
- 자동 중복 판별·자동 통합. 기획팀 수동 통합은 포함한다.
- 비밀번호 변경 시점 자동 강제 기능. 기획팀 수동 재설정은 포함한다.
- 파트너사별 서로 다른 공개 범위.
- 계약 한 건에 실제 도입 고객사 여러 곳을 연결하는 기능.
- 상시 엑셀 업로드 기능. 최초 자료 이전은 7단계 범위다.
- 확인하지 않은 외부 서비스 연동·운영 배포.
