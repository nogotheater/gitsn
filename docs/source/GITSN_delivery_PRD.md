# GITSN 납품현황 웹페이지 — 1차 PRD 및 구현 기준
확정 기준: 2026-10-15 · 바이브코딩 검토 반영

첫 성공 기준: 기획팀이 한 번 입력한 실적을 영업 담당자가 별도 PPT 재작성 없이 조회·출력한다. 상단은 핵심 PRD이며 아래 표는 구현·검수 기준이다.

| 항목 | 요구사항 |
|---|---|
| 1. 제품 목적 | 계약 기준 고객사 실적을 한곳에서 관리하고, 영업에 필요한 조건으로 조회·출력·PDF 저장한다. 엑셀→PPT→월별 업로드 작업을 줄이고 오류 대조를 쉽게 한다. 실제 납품 완료 여부는 관리하지 않는다. |
| 2. 주요 사용자 | 기획팀: 정보 입력·수정, 계정·비밀번호 및 공개 범위 관리. 영업 담당자·대표: 직원용 정보 조회·출력·저장. 파트너사: 허용된 정보만 조회·출력·저장. |
| 3-①. 고객사·계약 관리 | 기존 고객사 검색·등록·수정, 계약별 제품·수량, 장소별 실제 제품 선택, 계약 유효 여부, 집계·표시·공개 설정, 수동 중복 통합. 제품·수량은 계약에 한 번 입력하고 고객사 정보에는 합산해 표시한다. |
| 3-②. 실적 조회·집계 | 제품·고객 분류별 조회, 데스크탑 카드형·모바일 리스트형, 제품 마킹, 직원용 상세의 제품별 수량 합계. 고객사 수가 핵심 지표다. 파트너사는 공개 목록과 비공개 수만 보며 같은 조건의 총고객사 수는 직원과 동일하다. |
| 3-③. 고객사 리스트 출력·PDF | 로고·고객사명·제품·총고객사 수·분류별 수를 출력한다. 계약 상세·수량은 제외한다. 조회·출력·PDF에 같은 공개 범위를 적용한다. 출력 양식은 페이지 디자인 후 결정한다. |
| 4. 사용자 흐름 | 기획팀: 로그인 → 고객사 확인·등록 → 계약 입력·출처 정보 기록 → 공개 범위 지정 → 저장. 이용자: 로그인 → 권한에 맞는 현황 확인 → 조건 선택 → 실적 조회 → 출력·PDF 저장. |
| 5. 주요 화면 | 로그인 / 실적 현황(총고객사 수·조건 선택·데스크탑 카드형·모바일 리스트형) / 직원용 계약 상세 / 기획팀 고객사·계약 관리 / 기획팀 계정·공개 범위 관리 / 출력·PDF 미리보기. 실적 항목에는 심볼(고객사 로고)·고객사명·도입 제품을 표시한다. |
| 6. 완료 기준 | 아래 완료 기준표의 등록·수량·집계·권한·통합·출력 사례를 통과하고 실제 엑셀 자료를 대조한다. 미정 업무 규칙이 영향을 주는 항목은 확정 전 완료로 처리하지 않는다. |

**운영 규칙:** 열람자는 직원·파트너사 두 분류이고 파트너사별 공개 범위는 같다. 열람 범위는 직원·파트너사이며 작업 권한은 기획팀·일반 이용자로 구분한다. 기획팀은 직원 중 관리 권한을 가진다. 기획팀이 아이디·비밀번호를 관리하고 주기적으로 비밀번호를 재설정한다(주기 미정). 신규 고객사의 기본 공개 설정은 민간 비공개, 나머지 분류 공개로 적용한다. 기획팀은 분류 또는 개별 고객사를 대외비로 지정할 수 있다. 고객 분류를 변경하면 변경한 분류의 기본 공개값으로 공개 여부도 갱신한다(민간 비공개, 그 외 공개). 계약 기준 실적임을 화면·출력·PDF에 표시한다.

**고객 분류:** 중앙정부 / 공공기관 / 지방자치단체 / 지방자치단체 의회 / 금융 / 교육 / 해외 / 민간. 분류는 단일 선택이며 해외 금융기관은 해외로 분류한다. 서울시청과 서울시의회는 별도 고객사로 분류·집계한다. 지방자치단체와 지방자치단체 의회는 각각 수도권·충청권·호남권·영남권·강원권으로 세분한다.

**고객사 집계 규칙:** 계약 당사자·실제 도입 고객사·설치 장소를 구분한다. 기획팀은 집계 포함 여부, 고객사/설치 장소 표시 방식, 공개 여부를 별도로 선택한다. 집계 대상으로 선택한 동일 고객사는 제품·계약 수와 관계없이 한 곳으로 집계한다. 예외 등록은 자동으로 생성하지 않으며 실제 계약 당사자와 연결을 보존한다. 예외 고객사에도 같은 집계 규칙을 적용한다. 집계 대상으로 지정한 비공개 고객사도 총고객사 수에 포함하되 파트너사에는 개별 정보 대신 수만 제공한다. 예: 전체 100곳 중 공개 70곳·비공개 30곳이면 파트너사는 공개 70곳의 목록과 비공개 30곳이라는 수를 보고 총고객사 수는 100곳으로 표시한다. 제품·분류 등 조건을 선택하면 해당 조건을 충족하는 고객사만 집계한다. 비공개 고객사 수도 같은 조건으로 계산하며 같은 조건에서 직원·파트너사 총고객사 수는 동일하다. 파트너사에 비공개 고객사의 개별 정보는 표시하지 않는다.

**중복 고객사 합치기 — 확정:** 기획팀이 유지할 고객사를 선택하고 중복 고객사의 계약 내역을 모은다. 명칭·고객 분류·공개 설정이 서로 다르면 합치기 전에 적용할 값을 선택한다. 합친 뒤 중복 고객사 표시를 없애고 고객사 수·제품 마킹·제품별 수량을 재계산한다. 계약과 설치 장소의 연결을 보존한다. 동일 계약을 두 번 연결·합산하지 않는다. 통합 작업이 실패하면 일부만 반영하지 않고 통합 전 상태를 유지한다.

**설치 장소별 제품 표시 — B 방식 확정:** 기획팀이 각 설치 장소에 실제 설치된 제품 종류를 선택한다. 선택 가능한 제품은 해당 계약에 등록된 제품으로 한정한다. 계약의 모든 제품을 각 장소에 일괄 표시하지 않는다. 장소별 수량은 입력·관리하지 않고 계약 전체의 제품별 수량만 보존한다. 장소의 제품 마킹과 제품별 검색은 해당 장소에 선택된 제품 종류를 기준으로 한다.

**제품 마킹:** 색상과 알파벳을 함께 사용한다. Alpha-C=C, Alpha-I=I. 같은 제품은 중복 표시하지 않는다. 나머지 제품 기호와 색상은 [결정 필요].

**계약 유효성:** 유효 계약을 실적에 반영한다. 렌탈 종료 등은 기획팀이 수정하여 해당 계약의 실적 반영을 해제한다. 유효 계약이 하나라도 남으면 고객사 수는 유지한다. 유효 계약이 하나도 남지 않으면 고객사를 목록·집계에서 제외한다. 원본 고객사·계약 기록의 보존 방식 및 종료 제품 마킹·수량 합계 처리는 [결정 필요]이며 목록 제외를 기록 영구 삭제로 해석하지 않는다.

**계약·출처 추가 항목:** 계약 당사자·실제 도입 고객사·설치 장소를 구분하는 구조는 유지한다. 제품·수량을 고객사와 계약에 각각 입력·관리하지 않고 계약 입력을 원본으로 사용한다. 고객사 등록 화면에서 제품·수량을 받는 경우에도 해당 계약에 한 번만 기록한다. 위 확정 입력 목록 외에 필요한 계약 연결·유효 여부 등의 입력 방식, 출처 정보의 구체적 항목과 필수 여부는 [결정 필요]이며 임의로 필수 입력을 추가하지 않는다. 제품 수량은 계약별로 기록하고 직원용 고객사 상세에 제품별 합계도 표시한다(A 방식). 예: Alpha-C 10대 계약 뒤 5대 추가 계약이면 계약별 10대·5대를 보존하고 합계 15대를 표시한다. 주요 실적 화면과 고객사 리스트 출력·PDF는 제품 마킹만 표시하며 수량 합계는 제외한다. 종료 계약을 합계에서 제외할지는 [결정 필요]이다.

**기존 자료·수정 이력:** 사용자가 전달할 기존 엑셀을 확인한 뒤 자료 이전 방법을 하나씩 결정한다. 마지막 수정일을 남긴다. 상세 수정 이력에 관한 결정은 보류하며 구현 범위로 추가 확정하지 않는다.

**입력 오류·빈 화면 처리 — 확정:** 필수 항목 누락이나 수량 형식 오류는 해당 항목에 이유를 표시한다. 수량 허용 범위는 아래 미정 항목에서 확정한다. 로고가 없으면 기본 표시를 사용하고, 조회 결과가 없으면 결과 없음과 0곳을 표시한다. 저장 실패 시 입력 내용을 유지하고 재시도할 수 있어야 한다. 계약일은 비어 있어도 저장한다.

**구현 순서 — 확정**

| 단계 | 구현 범위 | 다음 단계 전 확인 |
|---|---|---|
| 1 | 고객사·계약·장소 관계, 등록·수정, 집계 | 중복 계약·제품 추가·집계 선택·장소별 제품 사례 확인 |
| 2 | 로그인·권한, 직원·파트너사 조회, 모바일·데스크탑 화면 | 비공개 개별 정보 숨김과 동일 조건 총수 일치 확인 |

| 후속 또는 실제 자료 확인 시 | 다른 표기 관리 여부, 기존 엑셀 항목 대응·누락·중복 확인 및 최초 이전 방식 |

결정값·기본값·허용 조합을 확인한 뒤 구현한다. 아직 정하지 않은 값을 코딩 도구가 임의로 확정하지 않는다. 확정 규칙의 구현은 진행하되 미정 항목에 의존하는 부분은 보류한다.

**최종 완료 기준 — 확정 기준과 미정 항목의 의존 관계**

| 확인 항목 | 통과 기준 |
|---|---|
| 등록·저장 | 확정 필수 항목으로 저장되며 계약일·로고·메모 없이도 저장 가능. 재접속 후 유지. 입력 오류와 저장 실패를 처리 |

| 제품 수량 | 계약별 10대·5대를 보존하고 직원용 고객사 상세에 합계 15대 표시. 계약 정보를 이중 합산하지 않음 |
| 장소별 제품 | 장소 A는 C, B는 I로 선택하면 해당 제품만 표시·조회됨. 장소별 수량 없음 |
| 고객사 집계 | 집계 대상으로 지정한 동일 고객사는 중복 없이 한 곳. 제품·분류 조건에 맞는 수로 변경. 집계/표시 조합 확정 후 확인 |

| 공개 설정 변경 | 분류 변경 시 민간 비공개·나머지 공개로 갱신. 분류 단위 설정과 개별 설정 충돌 규칙 확정 후 확인 |
| 계약 종료 | 유효 계약이 남으면 고객사 수 유지, 전부 종료되면 목록·집계 제외. 종료 제품 마킹·수량·기록은 미정 규칙 확정 후 검증 |
| 중복 통합 | 명칭·분류·공개 설정 선택 후 계약·장소 연결 유지. 이중 합산 없이 집계·마킹·수량 재계산. 실패 시 통합 전 상태 유지 |
| 출력·PDF | 같은 조건의 대상과 수가 일치하고 파트너사 공개 범위 유지. 계약 상세·수량 제외. 양식 확정 후 잘림·누락·페이지 나눔 확인 |
| 사용·권한 | 휴대폰·컴퓨터에서 조회·출력·PDF 저장 가능. 로그인 없이는 접근 불가. 일반 이용자 수정 불가. 기획팀만 정보·계정 관리 |
| 기존 자료 이전 | 기존 엑셀을 옮긴 뒤 원본의 고객사·제품·수량과 대조. 이전 방식은 파일 확인 후 결정 |

**PDF 디자인 — 후속 결정:** 출력 항목과 공개 범위는 기존 확정 기준을 유지한다. 용지 방향·배치·페이지 나눔 등 PDF 양식은 웹페이지 디자인 완료 후 그 디자인에 맞춰 결정한다.

**1차 제외:** 보안 분야(추후 추가 가능), 장소별 수량 관리, 고객 제시용 별도 보기, 지도형 보기, 메일 자동 입력, PPT 자동 제작, 정식 수정 요청·승인 절차, 사내 자료실 연결, 납품 완료 추적, 근거 자료 파일 업로드·보관. 추가 제외: 자동 중복 판별·자동 통합, 자유로운 PDF 편집기, 비밀번호 변경 시점 자동 강제 기능. 기획팀의 수동 중복 통합·수동 계정 관리·수동 비밀번호 재설정은 유지한다.

**AI 코딩 도구용 구현 지시문**

위 확정 요구사항과 구현 순서에 따라 한국어 웹페이지를 단계별로 구현하라. 각 단계의 검증이 끝난 뒤 다음 단계로 진행하라. 계약 당사자·실제 도입 고객사·설치 장소를 구분하고 계약·제품의 연결을 보존하라. 집계 포함 여부·표시 방식·공개 여부는 독립적으로 관리하라. 수량은 계약의 제품별 전체 수량을 저장하고 직원용 고객사 상세에 제품별 합계를 표시하라. 같은 제품 10대와 5대 계약은 합계 15대로 표시하라. 기획팀이 계약 종료를 반영하면 유효 계약이 남아 있는 고객사의 집계는 유지하고 유효 계약이 전혀 없는 고객사는 목록·집계에서 제외하라. 주요 실적 화면·고객사 리스트 출력·PDF에는 수량 합계를 표시하지 마라. 장소별 수량을 만들지 마라. 기획팀이 계약에 포함된 제품 중 각 장소에 실제 설치된 제품 종류만 선택하도록 하고, 장소의 제품 마킹과 제품별 검색에 그 선택을 반영하라. 계약의 모든 제품을 각 장소에 자동으로 표시하지 마라. 직원·파트너사 열람 범위를 구분하고 직원 중 기획팀에만 관리 권한을 부여하라. 권한은 서버에서 검증하고 파트너사에 비공개 고객사의 개별 정보·계약 상세·출처 정보를 전달하지 마라. 비공개 고객사의 수만 제공하고 총고객사 수는 직원과 동일하게 유지하라. 조건별 조회 시 공개·비공개 고객사 모두 같은 조건으로 집계하라. 고객 분류 변경 시 공개 여부도 변경한 분류의 기본값으로 갱신하라. 비밀번호는 안전한 해시로 보관하고 재설정 방식으로 관리하라. 데스크탑 카드형·모바일 리스트형에 로고·명칭·제품 마킹을 제공하고 고객사 리스트를 출력·PDF 저장하게 하라. 파트너사 출력·PDF에도 비공개 수와 동일한 총고객사 수를 반영하라. 계약일은 선택 입력으로 구현하고 위 확정 등록 항목 외에 임의로 필수 항목을 추가하지 마라. PDF 양식의 시각적 세부 구성은 웹페이지 디자인 후 결정하고 현재 임의로 확정하지 마라. 보안 분야와 고객 제시용 별도 보기는 1차 범위에서 제외하라. [제안]·[결정 필요]는 확정 요구사항으로 취급하지 말고 하나씩 확인하라. 기획팀의 중복 고객사 합치기는 유지할 고객사 선택, 상충하는 명칭·분류·공개 설정 선택, 계약 내역 통합, 중복 표시 제거와 집계·제품 마킹·수량 재계산 순서로 구현하라. 계약·설치 장소 연결은 보존하라. 중복 통합 시 같은 계약을 이중 합산하지 말고 실패 시 통합 전 상태를 유지하라. 제품·수량은 계약에 한 번만 입력하고 고객사 상세에서는 합산값을 표시하라. 화면별 역할표와 완료 기준표를 검증하라. 미정 항목에 의존하는 부분은 착수 전에 확인하고 완료로 표시하지 마라. 가상 계약 사례로 중복·제품 추가·집계 선택·공개 범위·계약 종료 동작을 검증하라.
